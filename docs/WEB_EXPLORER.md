# Web explorer — static research-receipt browser

`web/` contains a read-only, fully static TypeScript app (React + Vite) for
browsing the lab's committed research evidence: strategy stat blobs, simulated
equity curves and drawdowns, per-segment ("regime") stats, and the sealed
receipts' verification-relevant fields. There is no backend; `dist/` can be
served from any static host or subdirectory (assets use a relative base).

## What it shows

| Surface | Source (committed, read-only) |
|---|---|
| Strategy list + per-segment stats | `artifacts/carry_champion*.json`, `receipts/adaptive_mix_*.json` (`results.*`, `paper_sleeves.*`) |
| Equity + drawdown charts | `artifacts/carry_equity*.parquet` → `fixtures/equity/*.json` |
| Receipt list + verification panel | `receipts/*.json` copied verbatim → `fixtures/receipts/` |
| Digest resolution | export-time scan mapping embedded sha256 fields → committed files |

Honesty posture: the app renders fields **as stored** in the receipts and
labels everything `research_only` / simulated; it never asserts performance
claims and does not re-run verification. Its "client-side checks" panel is
informational — authoritative, fail-closed verification remains
`dipcatcher verify-research` (see `docs/RECEIPT_VERIFICATION.md`). NAV curves
are labeled simulated backtest artifacts, not live performance; proper scores
(Brier/ECE/log-loss) appear verbatim where receipts carry them (e.g.
`fx1.dip_bench/v1`).

## Fixtures

`web/public/fixtures/` holds small, committed JSON exports generated by:

```bash
uv run --no-sync python web/scripts/export_fixtures.py   # from repo root
```

The script copies `receipts/*.json` verbatim, exports the two committed carry
equity parquets to compact JSON rows, normalizes strategy stat blobs into a
`{segments, extras, provenance}` shape, resolves embedded `*sha256` digests
against committed files (raw bytes and canonical-JSON encodings), and writes
`index.json`. Receipts are immutable: if a sealed receipt changes, re-run the
script and commit the drift (a pytest guard flags it).

## Develop / build

```bash
cd web
npm ci                 # locked deps; node >= 20
npm run dev            # vite dev server
npm run build          # tsc --noEmit + vite build -> dist/ (static)
npm run preview        # serve dist/ locally
```

Charts are hand-rolled SVG (`src/lib/chart.ts` + `components/LineChart.tsx`):
linear/time scales, 1-2-5 "nice" ticks, and min-max bucket decimation that
preserves peak/drawdown extremes — no chart dependency.

## Tests

| Suite | Command | Covers |
|---|---|---|
| Unit (vitest) | `cd web && npm run test` | scales/ticks, min-max decimation, drawdown math, hash-field extraction, index validation, hash router, table shaping — incl. real-fixture reads |
| E2E (Playwright) | `cd web && npm run build && npx playwright install chromium && npm run test:e2e` | overview load, strategy detail + chart render, receipt verification panel, hash routing, console-error smoke; `webServer` serves `vite preview` on `dist/` |
| Fixture guard (pytest) | `uv run --no-sync pytest tests/unit/web_explorer -q` | fixture↔receipt byte equality, index references, series ordering/finiteness, honesty flags |

CI: `.github/workflows/web_explorer.yml` (separate from `ci.yml`) runs
`npm ci`, vitest, `npm run build`, uploads `dist/`, then installs Chromium and
runs Playwright on ubuntu-latest. It triggers on `web/**`, this workflow file,
`receipts/**`, and `artifacts/*.json` changes.

## Deploy

Any static host that can serve files:

```bash
cd web && npm ci && npm run build
# publish web/dist/ (e.g. GitHub Pages, S3+CDN, nginx) — no server config
# needed; hash routing avoids SPA rewrite rules.
```

## Limitations

- Fixtures are a snapshot: new receipts/artifacts appear only after re-running
  the export script and committing (by design — sealed, reviewable data).
- Digest resolution covers the current checkout only; "unresolved" means the
  hashed input is sealed data outside the repo or an older revision — it is
  not a verdict.
- No equity series exist for the adaptive-mix allocator/sleeve entries (the
  sealed receipt carries segment stats only); those entries show stats tables.
